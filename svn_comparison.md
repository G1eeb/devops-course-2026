# SVN vs Git

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на конкретный коммит (по сути, файл размером около 41 байта). Создание, переключение и удаление ветки происходят мгновенно и не дублируют файлы проекта. В SVN ветка — это копия директории на центральном сервере, поэтому создание ветки занимает место и время, а операции с ней идут по сети.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: коммит всегда уходит на сервер и фиксируется в его репозитории. Без сети можно редактировать файлы локально, но зафиксировать изменения (commit) нельзя. В Git коммит делается локально в собственном репозитории и не требует сети — синхронизация с удалённым сервером (push/pull) выполняется отдельно.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты, которые уже много лет на SVN: стоимость миграции выше, чем поддержка текущей системы.
- Жёсткий централизованный контроль версий (госсектор, банки), где нужна единая точка хранения и администрирования.
- Очень большие бинарные файлы (графика, видео, CAD), из-за которых Git-репозиторий раздувается. Частично решается Git LFS, но не всегда удобно.
- Команды с жёстким разделением прав по директориям — в SVN это настраивается проще.
